# K2 data cube

Generated by `python3 etl/fetch_data.py`. Do not edit by hand.

## Files

| File | Contents |
| --- | --- |
| `catalog.json` | sections, variables, objects (20 + 40 grid), series index, phenomena, hypothesis chains, meta |
| `series.json` | normalized monthly/annual series keyed by `object|variable` |
| `meta.json` | compact build metadata |
| `geo/kyrgyzstan.json` | 7 ADM1 region polygons (d3-geo winding: clockwise exterior) |
| `geo/kyrgyzstan.geojson` | same, GeoJSON |

## Period and units

- Period: 2000–2025, monthly step unless `nativeStep: "year"`.
- Temperature: °C; precipitation/evaporation/snowfall: mm/month (annual = sum, mm/year);
- soil moisture: % (root-zone wetness × 100); snow depth: cm;
- lake level: m (reconstruction, annual); snow season: days/year; global temp: °C anomaly; CO₂: ppm.
- Missing values are **not** stored and **not** interpolated.
- Outliers are **not** removed; the pipeline keeps them and the UI can mark them.

## Real vs reconstructed

- NASA POWER (MERRA-2 / GLDAS / GPM IMERG) — real reanalysis/model output via the open POWER API.
- NOAA NCEI / GML — real monthly global temperature and CO₂.
- GeoBoundaries — real ADM1 boundaries (ODbL).
- Issyk-Kul level — **reconstruction** anchored to Zhang et al. (2022), Remote Sensing 14(7), 1575. Not raw Hydroweb. The UI labels it and the analysis caveat says to use Hydroweb/DAHITI for official work.

## Why no MODIS NDVI / snow cover in this build

The public ORNL MODIS subset API takes ~60 s per point-year for a 26-year series; a reproducible build for 10 objects would take hours. The ETL keeps the adapter code, but the default build skips it. Snow-season length is derived from daily NASA POWER snow depth and explicitly marked as a proxy.

## Regenerate

```bash
python3 -m pip install -r etl/requirements.txt
python3 etl/fetch_data.py
```

Raw API responses are cached in `etl/.cache/` (gitignored). The ETL is idempotent.
